## Risk & Assumption Register

### Risks
| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Mock complexity for account.Manager (15 methods) makes tests brittle | Medium | Medium | Sensible defaults in mock — most tests only exercise 2-3 methods |
| Worktree merge conflicts if test files import shared helpers differently | Low | Low | All tests import same `mocks_test.go` and `loadgen_test_helpers_test.go` — these are in base branch before worktrees fork |
| `workers.go` concurrency tests are flaky due to timing | Medium | Medium | Use channels/sync primitives for synchronization, not `time.Sleep` |
| WebSocket tests require complex mock infrastructure | Medium | Low | Test the event *handling* logic, not the WS connection itself |
| Coverage numbers don't improve meaningfully despite tests | Low | Medium | Target specific functions, not just line coverage. Verify with `-coverprofile` per file |

### Assumptions
1. `refactor/split-main-go` branch is stable and all existing tests pass
2. No other work is happening on this branch during the testability push
3. Go 1.25 is available and working in the loadgenerator repo
4. The functional options pattern (`WithXxx`) is acceptable for constructor injection (vs changing the signature to accept all deps directly)
5. Hand-written mocks are sufficient — no mocking framework (mockgen, etc.) needed
6. WebSocket handling can be tested by testing the callback/handler functions directly, without standing up real WS connections
